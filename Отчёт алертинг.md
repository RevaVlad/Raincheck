# Алертинг Raincheck

Выбраны три алерта на существующих метриках: два проверяют работу сервиса, один — загрузку процесса Node.js. Новые метрики не требуются.

| Алерт                | Метрика                                   | Условие                                                                                     | Длительность нарушения |
| -------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------- | ---------------------- |
| Ошибки пробера       | `raincheck_probe_checks_total`            | Есть неуспешные проверки в скользящем окне 30 секунд                                        | 1 минута               |
| Высокая задержка     | `raincheck_probe_duration_seconds_bucket` | p95 за 5 минут выше 500 мс для `poll_read` или 1 с для `availability_save` и `common_slots` | 3 минуты               |
| Высокая загрузка CPU | `process_cpu_seconds_total`               | Среднее потребление CPU за 5 минут выше 0,8 ядра у экземпляра API                           | 5 минут                |

Ошибки пробера отражают доступность и корректность пользовательских сценариев. Задержка проверяет целевые времена ответа: в p95 учитываются корректно завершённые проверки с результатом `success` или `slow`. CPU показывает устойчивую нагрузку на рантайм. Выдержка перед срабатыванием отсеивает кратковременные сбои и всплески.

vmalert проверяет правила каждые 15 секунд, Alertmanager отправляет в Telegram уведомления «Проблема» и «Восстановлено» с описанием алерта. Используются стандартные интервалы Alertmanager: ожидание первой группы — 30 секунд, проверка изменений группы — каждые 5 минут, повтор неизменившегося уведомления — через 4 часа. Они добавляются к задержкам правил.

Alertmanager установлен через чарт `prometheus-community/alertmanager` версии `2.3.0` (Alertmanager `v0.34.2`). Чарт создаёт StatefulSet и постоянное хранилище; в values заданы получатель Telegram, шаблон сообщения, прежние интервалы уведомлений и объём PVC 1 GiB. Временные отключения алертов и журнал отправленных уведомлений сохраняются при пересоздании Pod. Telegram Secret создаётся из файла `alerting.env`.

Команды запуска приведены в [k8s/README.md](k8s/README.md#уведомления-в-telegram).

Интерфейс алертов:

```
kubectl port-forward -n monitoring deployment/raincheck-vmalert 8880:8880
http://localhost:8880/vmalert
```

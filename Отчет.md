# Стратегии развёртывания Raincheck

Возвращение к версии v1, создание трафика

```bash
bash k8s/reset.sh
bash k8s/traffic.sh
```

## Rolling Update

```sh
kubectl patch -n raincheck deployment/api --type=strategic --patch-file k8s/strategies/rolling.yaml
```

## Запуск отдельного деплоймента новой версии

```sh
kubectl apply -f k8s/strategies/api-v2.yaml
kubectl rollout status -n raincheck deployment/api-v2
```

Откат настроек трафика

```sh
kubectl apply -f k8s/strategies/baseline.yaml
```

## Blue/Green

Переключите весь трафик на `v2` одной командой.

```sh
kubectl apply -f k8s/strategies/blue-green.yaml
```

## Canary

Доли `v1/v2` меняются в порядке 90/10, 50/50 и 0/100.

```sh
kubectl apply -f k8s/strategies/canary-90-10.yaml
kubectl apply -f k8s/strategies/canary-50-50.yaml
kubectl apply -f k8s/strategies/canary-0-100.yaml
```

## A/B

Разделение по заголовку `X-User-Group: beta`

```sh
kubectl apply -f k8s/strategies/ab.yaml
```

Запуск потока с заголовком `beta`

```bash
$env:RATE="2"; $env:LOCAL_PORT="8889"; $env:USER_GROUP="beta"; bash k8s/traffic.sh
```

## Shadow

Примените маршрут с зеркалированием `GET /api/version` на `v2`. Клиент продолжит получать ответы `v1`.

```sh
kubectl apply -f k8s/strategies/shadow.yaml
```

Логи `v2` с копиями запросов:

```sh
kubectl logs -n raincheck -l app=api-v2 --prefix --since=1m -f
```

## График запросов по версиям

```promql
sum by (version) (
  increase(http_request_duration_seconds_count{route="/api/version"}[20s])
)
```
